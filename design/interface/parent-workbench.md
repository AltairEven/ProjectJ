# 家长工作台

文档版本：1.1.1；更新：2026年10月12日；范围：逻辑设计，未实现。

工作台让家长知道当前重点、下一步行动与依据，以准备下一课、处理必要条件和查看反馈为主。interface呈现各业务模块的权威结果，不另建能力评级、计划、教案或评价副本。

涉及继续条件的“关键”与阻断判定，统一采用[共同阻断标准](../shared/business-contracts.md#关键阻断的共同标准)。

## 入口与信息组织

| 区域 | 显示 | 操作与责任 |
| --- | --- | --- |
| 下一堂课 | 目标/理由、基本预期、实际课程版本、备课/本次状态与缺口 | 请求备课、预览、补充条件、进入启动检查，由相关模块判断 |
| 学习与计划 | 当前重点、相关全学科能力/未知、本周安排与家庭预算 | 查依据、提出调整、处理重大决定，不要求家长逐科评级 |
| 课后结果 | 最近活动、帮助/实际表现、课堂对照、下节预期与修订 | 提交反馈、更正事实、展开证据，evaluation维护原记录 |
| 待处理事项 | 关键澄清、材料/能力缺口、必要决定、保存或下游处理失败 | 显示具体原因和下一步，恢复原对象/修订，不重复创建成果 |
| 内容与历史 | 课程/素材候选、版本、真实使用与更正限制 | 查阅、选候选或请求复用/修订，内容库候选不自动替换计划 |

首页优先显示下一课、最近结果和必要待处理项，其余按需展开。年龄等背景由参考日期推算，状态由有据反馈更新，不做每日档案填写。学科/课型变化仍为Jane，不提供教师阵容。

工作台按[学习者归属](../learning/profile.md#学习者归属与扩展边界)取得当前孩子的结果和待办。待办身份包含所属学习者及原对象/周期；未来家庭汇总视图须保留归属，不能把同名活动或同周期复盘合并。切换孩子不改写已发起操作或迟到结果的归属，当前单学习者界面也保留这个边界。

## 有依据的状态与下一步

状态同时说明对象/实际版本、判断范围、未知/缺口和可执行下一步。例如“课程包已备好，本次声音待检查”，提供当前检查入口；不能只显示一个绿色就绪标记。草案预览、家长实际阅读、备课完成、本次可开课、已使用和实际报告分别显示。

已知条件与授权不重复询问，常规小调整由业务模块落实并说明；重大方向、学科优先级、固定预算和主要教学/评价方式按具体方案取得家长决定。界面展示选择和实际反馈，不擅自扩大授权或把浏览方案当接受。

待处理项应关联原需求、课程、活动或问题，展示主责/处理结果，避免同一问题在多个模块出现互相竞争的结论。请求已受理、处理中、成功、失败或仍未知来自实际结果，点击按钮不直接宣布完成。

## 课中家长职责

家长可通过必要控制暂停/停止、报告额外帮助或接手；默认不要求频繁操作、逐句转交和逐题评分。接手来源与[角色切换](roles-devices.md)明确，不能把家长补充算孩子回答。

课中只使用核心已有的必要状态/控制，不新增屏幕监控、课堂快照、原始音频归档或额外Agent检查。详细教案/答案仅在适合家长角色的范围获取，查看或代答前按暂停路径处理，回到原会话接续。

课前走[预览与启动](preview-start.md)，课后走[反馈与报告](feedback-reports.md)。

## 复盘与决定入口

正常打开工作台或完成课后处理时，请learning核对[复盘条件](../learning/plan-review.md)。显示同一计划周期的待复盘事项，支持开始、稍后处理及主动发起；日期到达不自动标计划完成，不依赖外部定时任务。

重大方案展示明确版本、原安排、拟变化、影响、替代和复查条件，家长的决定连接该版本。依据变化后需复核的方案不能直接应用旧接受；展示已接受与已实际落实的区别。应用层返回步骤结果，界面不另维护方案的业务结论。
