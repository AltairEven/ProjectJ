# 周阶段年度计划复盘

版本：1.2.0；更新：2026年10月20日；范围：逻辑用例。

learning维护复盘事项、综合结论和计划修订，应用协调层负责发起后的执行与失败接续。evaluation提供已有事实、评价及跨课对照，teacher独立处理方法改进，学生决定重要方向与投入变化（[ADR-0018](../../decisions/ADR-0018.md)）。

## 触发与输入

| 触发 | 处理 |
| --- | --- |
| 学生主动请求 | 指定周、阶段、年度或长期范围；缺省取当前相关计划 |
| 到期 | 打开主页面或链路每完成一段时，应用协调层核对复盘日期，到期即由AI自动发起；同一计划周期只发起一次 |
| 初期阶段第四周与周期末 | 按现有八周计划回看证据、预算、活动适配与下一阶段需求；周期可经计划修订变化 |
| 年度节点或重要条件变化 | 回看年度重点，必要时复查长期方向；年龄/日期变化不生成能力进度 |

到期自动发起复盘，但不自动结束阶段。首版依靠正常应用访问触发，不创建外部定时任务；同一到期事项不重复发起、弹窗催促或新增学习样本。

输入包括计划实际版本/范围、已保存评价与状态、覆盖/帮助/保持迁移证据、课堂对照与问题处理结果、家庭时间/体验变化、材料经历和待反馈/缺口。声明数据截止范围；跨课汇总引用原样本，不能把同一次表现重复计数。

复盘事项以学习者、计划及周期定位，证据汇总、待决定方案和发布目标均核对同一学习者，采用[档案归属规则](profile.md#学习者归属与扩展边界)。

## 执行顺序

| 步骤 | 责任与结果 | 接续条件 |
| --- | --- | --- |
| 1. 建立复盘 | 应用层定位原事项/操作；learning固定计划基线和所取来源 | 同一请求重试原操作；范围不明只补必要信息 |
| 2. 整理依据 | evaluation提供实际表现/课堂对照与限制；learning核对状态和计划差异 | 来源已保存；不足部分明确，仍处理有据范围 |
| 3. 形成结论 | learning提出继续、缩小、观察、调整或结束阶段的理由 | 未达目标可延续，不凭课时或日期宣告掌握 |
| 4. 分派变更 | 本周/下一课小调整在授权内落实；年度优先级/固定预算等生成待决定方案；teacher处理方法候选 | 常规与待决定分别保存，互不扩大授权 |
| 5. 保存生效 | learning核对当前版本，保存复盘/计划修订或沿用结果 | 冲突重核新增依据，不覆盖后来反馈；接受方案也需保存成功 |
| 6. 重核后续 | learning生成/复核需求，preparation重核受影响已备包 | 只对相关变化复核，应用层汇总实际结果给学生 |

周复盘优先调整近期活动组合；阶段复盘决定阶段目标/支持/验证是否继续；年度复盘处理学科投入和长期路线适配。下层小调整不自动重写所有上层计划。

首版由学习规划模型提出结论、未知、下次复查条件与可选计划补丁，规则分派：周计划补丁直接生效，其他层级形成待决定方案，预算改动与目录外目标不生效并记入核对说明；学生自己提出的补丁仍按原流程形成方案；待决定方案在学习计划页由学生同意或不同意。复盘保存模型草稿，重试按草稿接续，不重复调用模型。

## 缺口与失败

缺少保持/迁移或某学科样本时，可保存“暂不调整、下次观察什么”的结论；不要求先补齐全科测评。延后反馈是否影响某项调整按[继续条件](../shared/execution-recovery.md)核对。

证据汇总失败保留原来源；计划保存失败不宣布已调整；复盘保存成功而需求失败，从需求步骤接续。部分阶段已实施后重试时，读取新有效版本再判断原建议是否仍适用。重大方案待学生或过期时，受它影响的发布等待，其余已授权工作继续。

复盘记录含触发、覆盖区间、基线、证据截止、结论/未知、变更及采纳理由、待决定方案、实际保存/生效范围和下一复查条件。学生只补事实和作重要选择，不手工给全科能力评级。验收见[端到端案例](../shared/end-to-end-cases.md)。
