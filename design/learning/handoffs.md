# 模块交接与设计检查

版本：1.4.0；更新：2026年10月12日；范围：逻辑设计，未实现。

交接传递相关依据和需求，不复制整份档案、全部历史或整段规划聊天。这里规定责任和信息内容，不选择API、JSON Schema、数据库或调度机制。

## 评价交给学习管理

[evaluation](../evaluation/README.md)维护最终实施记录、证据和本次评价；learning维护跨课状态与计划。评价判断任务表现，学习管理检查证据适用范围并落实修订，不建立第二套逐题评分。

| 交接内容 | 要求 |
| --- | --- |
| 活动与来源 | 活动标识、修订、真实发生日期、儿童/成人/技术分类、结束原因 |
| 课程与材料 | 实际使用的课程版本、任务、材料及评价条件；课外来源注明实际来源，不虚构课程 |
| 各维度实际表现 | 相关学科/能力范围、原答或作品引用、AI和家长帮助、首次与帮助后表现 |
| 完成与未知 | 实际取样、未做/未报告、识别不清与来源冲突；离屏和确认不得代填 |
| 判断与建议 | 有证据的工作判断、状态修订依据、保持/迁移、体验负担、下节建议与待核实项 |

评价意见不是自动全科升级指令。常规有依据的修订由学习管理落实并说明，必要澄清只针对当前关键缺口。同一活动的评价更正需连接原修订，防止再次计为新样本。

周与阶段复盘可由评价模块综合相关证据提供结论；学习管理据此调整计划，不将复盘自身计作新学习活动。

按[评价交接](../evaluation/handoffs.md)取得实际来源/修订、任务条件与状态依据，以及[备课课堂对照](../evaluation/lesson-alignment.md)的差异/原因/许可/影响。learning不将覆盖率或运行问题当能力，不再逐题评分；落实或部分失败返回实际处理范围，同一修订不重复计样本，更正与新状态并存时核对受影响依据。

## 学习管理交给备课

[preparation](../preparation/README.md)接收[下一课需求](plans.md)，至少包含：

- 需求标识与修订、学习者标识、相关档案/状态/计划版本及上级目标。
- 一个主要和一个辅助目标；巩固、拓展或进阶的依据及基本预期。
- 相关学科、跨学科能力和工具前提的状态摘要、材料经历、帮助与证据引用；未知和待验证假设明确。
- 实际时间、材料、陪伴等条件；家庭预算来自已确认条件，不把可用时间排满。
- 需要复习的真实旧知或无儿童历史分支、首次尝试、独立验证、保持/迁移或离屏需求。
- 预计帮助、纠错重点、可选挑战、退回与停止条件；通常只增加一种主要难度。
- 关键缺口与允许的替代范围，不把下一课建议标成已就绪课程。

备课只读取相关摘要与必要原证据。其他学科状态在涉及先备、融合或计划取舍时读取，不将“英语优先”当成只能访问英语，也不把全学科档案全部塞进每次模型上下文。

课程候选由[curriculum索引](../curriculum/discovery-reuse.md)按目标/能力/条件返回，learning/preparation结合真实状态和材料熟悉度选择，不由内容库生成能力或替换计划。学科/能力/概念标识引用统一目录，索引标签不成为学生等级。
## 备课的返回与课程绑定

备课返回需求引用、课程草案/版本、目标与任务对应、材料与核验状态、一页预览及就绪缺口。发现材料不可得、先备不符、预算不够或评价任务不合适时，提出有依据的替代与影响；学习管理在既定范围内修订需求，重要目标或评价方式变化请家长决定。

生产组织见[备课输入流程](../preparation/inputs-workflow.md)与[版本交接](../preparation/versions-handoffs.md)。备课返回[课程包/简报](../preparation/course-package.md)、实际素材、核验与预览及完成范围；[本次开课条件](../preparation/readiness.md)由classroom/platform/interface另行核对。learning提出需求、课程包保存或预览可用不等于设备与家庭当下已就绪。

常规生成和核验由备课承担，不把所有未知变成家长材料清单。关键背景缺口可安排课内轻量观察；核心内容或运行缺口则保留未就绪，不以降低验收要求绕过。

[curriculum](../curriculum/README.md)管理最终课程与素材版本。课程包连接所用需求、计划和状态依据，以及实际Jane配置/启用策略版本与本课简报；[classroom](../classroom/README.md)绑定这些内容，仅取得本课必要背景，在原有时间内执行，正常结束或明确停止后交回实际记录。learning不直接安排每一轮教师话术或控制播放。

## 与唯一教师Jane的衔接

[teacher](../teacher/README.md)维护Jane唯一身份、规则、学科/课型策略和改进版本；本模块维护学生档案、全学科状态与计划。需求通过相关摘要为Jane方法选择提供依据，不将全份档案复制为教师专属记忆。

preparation按[teacher交接](../teacher/handoffs.md)选择方法并编制本课教师简报，curriculum保存实际绑定与历史。evaluation分别向learning提供状态依据、向teacher提供行为改进依据，同一来源不重复计样本；Jane方法变化也不能自动生成学生能力增长或改变长期目标。

## 版本、修订与来源切换

- 档案、状态、计划、需求、课程、活动记录和评价相互引用实际版本，Git历史不能代替业务修订依据。
- 备课期间出现新状态时，检查其对本课的影响。只修改受影响部分；关键先备、目标或评价条件改变时须重新核对相关课程内容与就绪依据，不能默默沿用过期需求。
- 已实施课堂保留当时课程与条件，后续状态改变不改写历史。实际事实更正则留更正说明并重审依赖结论。
- 内容错误按[课程历史更正](../curriculum/history-corrections.md)回查实际使用与评价，learning基于更正依据重审相关状态和未来计划；更正不改变原答、增加活动日期或将成人资料当儿童证据。
- 最终记录、状态修订和计划调整应能解释各自保存是否完成；冲突或部分失败不能冒称全流程成功，恢复后同一来源不重复计入。
- LearningWithAI当前仍是档案与历史证据权威。未来迁移必须明确唯一维护入口、来源/标识映射、证据可访问性、版本兼容与更正历史；不先自动导入、双向回写或丢弃旧记录。

## 家长界面的最小结果

[interface](../interface/README.md)呈现当前重点与依据、全学科状态中的相关维度和未知、本周预算、下一课预期、最近变化及关键待补信息。详细证据与历史按需展开；家长可更正事实，但不要求逐科评级或逐项批准常规修订。

## 未来实现需要验证的场景

| 场景 | 必须得到的结果 |
| --- | --- |
| 没有新学习反馈，日期跨学年 | 只重新计算背景，不生成能力、材料进度或完成记录 |
| 新增数学或历史活动 | 可复用状态/证据/计划框架，采用学科自己的任务与评价依据，不只能处理英语 |
| 同一融合任务中中文解释独立、英语需句框 | 分维度记录条件，综合完成不使全部学科升级 |
| 同一活动补充作品或更正帮助 | 修订原来源并重审关联结论，不增加活动日期或独立样本 |
| 新难题失败、旧简单任务已有证据 | 保留旧范围，记录新范围困难；不统一降低学科等级 |
| 旧样本很久未复查、保持未观察 | 标注适用范围并安排短复查，不自动退步或宣称保持 |
| 离屏未报告或活动提前停止 | 保留未知和未完成项，记录可收尾，不能补造动作或正常小结 |
| 成人演练、技术模拟或仅有教师示范 | 成人与模拟不进入儿童状态或进度；仅有示范不证明能力，实际材料接触与帮助后尝试分别保留 |
| 备课前提改变、材料缺失 | 修订受影响需求/课程并保留缺口；建议不自动变成可开课 |
| 常规巩固调整与学科优先级改变 | 前者由AI落实并解释，后者提供具体方案交家长决定 |
| 状态保存失败或两个来源冲突 | 明确未完成部分或保留冲突，从同一修订接续，不重复计样本 |
| 导入旧项目数据 | 来源和引用可追溯，维护入口唯一，成人历史不转成儿童证据 |

这些是设计检查与未来验收要求，本轮没有实现或执行上述程序场景。原型课程、回归测试及链接检查通过不能证明学习管理功能或教学效果已经验收。总验收入口见[验收标准](../../docs/acceptance.md)。
