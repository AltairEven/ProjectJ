# 评价输入与家长反馈

文档版本：1.3.1；更新：2026年10月12日；范围：逻辑设计，未实现。

evaluation接收结束封存事实，并结合当时内容、已经提交的家长反馈及必要历史形成有范围的解释。它处理统一业务输入/输出，interface负责收集与呈现，platform提供模型和存储等能力。

涉及继续条件的“关键”与阻断判定，统一采用[共同阻断标准](../shared/business-contracts.md#关键阻断的共同标准)。

## 输入来源

| 来源 | 内容与限制 |
| --- | --- |
| classroom | 活动用途/实际日期/结束、输入与原答、判断/帮助/再试、动作/交付/确认、指认离屏、时间与实际素材；缺失保持缺失 |
| curriculum/preparation | 当时固定课程/任务/素材、评价依据、Jane简报、目标/预算、核心/可选及允许分支、核验范围；计划不证明实施 |
| 家长/孩子 | 通过interface提交的实际原话、体验、额外帮助、作品/离屏结果和条件；提供者、发生日期与报告日期分别保留 |
| learning/历史评价 | 相关能力范围、帮助/材料经历、原状态及必要保持/迁移证据；不加载全份档案与全部历史 |
| teacher/平台信息 | 当时方法版本、技术反馈和实际能力限制，用于行为/问题定位，不自动当学习证据 |

输入关联活动/修订、来源、当时对象/版本和取得范围。识别文本、孩子自述、家长报告、直接取得作品、模型解释及运行结果分别识别；未知不补成儿童独立表现。只有教案或模型生成内容不能补成实际事件。

## 结束封存与反馈入口

按[共同执行](../shared/execution-recovery.md)，classroom确定活动结束后，evaluation接收已有事件、绑定和结束范围，先作结构/来源边界核对并保存封存事实；不等待家长反馈或模型总结。正常结束、收尾未确认、明确停止和可控中断保留各自原因，暂停不当结束。

封存成功后可以稍后提交反馈。阶段性评价仅由应用层按[按需触发与复用规则](../shared/execution-recovery.md#阶段性评价的按需触发)请求：家长已明确稍后反馈，且准备下一课或工作台当前用途确实需要。evaluation不监听封存成功就自行调用模型；只有保存且证据支持的部分可交learning，帮助/作答者/材料条件缺失不默认为独立。家长反馈追加原活动后形成最终整理或必要更正；无新事实且已有结果足够时复用结论，最终仍保留未知且允许以后补充。

成人演练与技术模拟维持来源分类；课外作品、学校反馈等按真实来源直接接收，不虚构AI课堂或要求封存一场不存在的课堂。丢失事实按实际可提供的来源补记，不从教案或后来的模型输出还原原答。

## 家长一次反馈

家长补充课堂无法取得的信息即可：实际体验或孩子原话、家长额外帮助/代答、离屏或作品结果、熟悉材料，以及准备/陪伴负担和下次条件变化。不要求逐题打分、完整逐字稿、手工能力等级或重复基本档案。

“没有额外补充”可作为明确提交，“没观察到”表示该范围未知；都不代表所有任务独立、声音顺畅或全部完成。反馈与课堂事件合并到同一活动，来源相同不增加独立样本。

interface支持文字、语音等实际入口，evaluation取得原话/可获取内容、说话者与识别限制，不直接录音或排版。自动结构化的摘要不能覆盖原话，家长可更正事实；具体采集方式由后续界面设计确定。

具体一次反馈与提交状态按[界面反馈/报告](../interface/feedback-reports.md)收取，角色/设备与实际提供者按[切换规则](../interface/roles-devices.md)区分；学生页或账号收音不证明孩子作答。重试关联原提交/活动，明确无补充不推定独立/顺畅，未提交草稿不自动当实际反馈或归档。

## 关键澄清与冲突

只补会改变当前判断或下节安排的缺口，例如谁实际作答、内容帮助是否发生、材料是否熟悉、离屏结果/日期冲突。先处理有依据部分，其他未知不要求填满；追问不变成第二次课堂或课后补测。

冲突保留双方来源，核对是否对应同一任务/时间/条件，再必要澄清。原事件和家长报告都不自动成为唯一正确答案，不能用模型多数意见裁定事实。确认前限制相关判断，不为凑完整报告编造原因。

输入核对及记录见[facts-evidence.md](facts-evidence.md)，本课评价与备课对照见[assessment.md](assessment.md)、[lesson-alignment.md](lesson-alignment.md)。
