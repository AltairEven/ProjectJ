# 共同业务对象与维护责任

文档版本：1.4.0；更新：2026年10月16日；范围：业务合同及P0/P1工程映射。

合同规定所有模块共同采用的含义与最少联系，P0字段供阶段1落实；工程映射不能替代本合同。业务维护者解释并修订对象，platform负责物理保存和访问，interface呈现实际结果；存储位置或模型调用方不改变业务权威。

## 共同身份时间与版本

每个对象保留稳定身份、业务修订、维护者、来源/原操作联系、适用范围与依赖实际版本。个人学习对象显式绑定稳定学习者标识；一名学习者一套状态/计划，个人与共享对象的范围按[档案归属规范](../learning/profile.md#学习者归属与扩展边界)执行。跨模块关联、读取、重试和发布核对该归属，不能由当前页面或同一家庭账号代替；共享内容/技术报告声明复用范围。名称只供阅读，不能凭同名或最新链接合并。文档版本、业务修订、Git提交和服务商模型信息分别标识。

实际发生日期、接收/上传日期、评价/修订日期分开；未知时间不补造。来源类型保持儿童真实、成人演练、技术/明确模拟和课外真实来源，不因切视图、报告样式或模型重评转换。

正式对象读当前有效修订，引用历史时取得实际旧内容。档案/状态/计划/需求/方法正式修订取得保存成功及所需业务检查后生效；生成、受理和候选不等于生效。课中核心状态是内存运行状态，不受此长期保存条件阻塞。

## 任务尝试与技术重复

| 单位 | 含义 |
| --- | --- |
| 任务定义 | 所属课程/模板中的任务及实际内容、材料和评价条件版本 |
| 任务实例 | 本堂活动采用该定义、实际素材/变式及当前取样条件的一次任务安排 |
| 尝试 | 针对实例实际收到的一次完成回答/作品/动作报告，记录来源与当时帮助 |
| 输入事件 | 一次实际提交及其身份/顺序，可能包含答案、控制、确认或更正；片段不自动成为尝试 |
| 技术重发 | 同一事件/操作再次传输，保持身份，不再推进或计样本 |
| 事实/识别更正 | 关联原尝试与来源修订，保留原取得内容，不制造新发言 |

按[输入提交分界](../interface/input-submission.md#补充再试与评分异议的分界)，回应实际交付后的新发言按当前等待对象处理；只有回应未交付前的补充回连原事件，纠错后改答不能当作初答补充。同题再答是新尝试但仍关联原实例；新材料或新的取样条件形成可区分的实例，不能仅改身份就宣称独立。重复播放不是再答。两次真实同句回答不按文本去重；两个课程任务同名不自动合并。

课堂作答为文字/点选提交，不设语音识别；朗读录音只交发音评分，评分结果保留服务、版本与限制。所有尝试可关联同一活动，跨维度引用、摘要、复盘和多模型重评不增加活动日期或独立样本。

## 帮助交付与证据

帮助共同分类为无内容帮助、轻提示、支架、完整示范、未知。按任务实例/受影响学科能力记录来源、实际内容/方式、交付范围和影响；单纯重复要求、允许图片是否构成内容帮助由本题条件决定。

拟议、允许、实际交付、学生确认收到和表现出理解分别连接。未交付示范不记成已经帮助，收到不明不默认独立；同一实例/维度已发生的最强帮助不随换指导降低。新任务减少支持可取新的条件样本，但保留材料熟悉度与前题泄露的影响。

证据连接原活动/任务/尝试、来源修订、实际材料/日期、提供者、帮助/媒介及支持范围。未知不转成0分、不会、完全独立或通过。模型提出解释不是新的观察，模型不评价发音；英语发音只采用发音评分能力对课程包标注的朗读/跟读评分段给出的结果，带服务与版本，不同服务或版本的分数不直接比较，录音过短、嘈杂、未读或评分失败记未知（[ADR-0014](../../decisions/ADR-0014.md)）。材料接触可影响后续选材，但来源和接触范围须有据。

## 处理结果与失败联系

交接说明调用方、用途、输入对象/修订、期望适用基线、原操作身份、允许范围和期限/取消。结果保留接收、处理中/待必要输入、已生成、保存成功或失败/未知、实际生效范围、冲突/取消、缺口与下一步。这些是不同结果维度，不用一个绿色完成替代。

无修改也返回“已核对、沿用哪个有效版本及范围”；不适用有理由。保存结果未知先查询/核对原操作，不能猜未执行再创建。来源修订未变且已处理的步骤不重复执行；新更正联系原活动并重审相关依赖。

应用层按[执行约定](execution-recovery.md)协调，业务模块仍裁定适用性。改进问题区分待定位、待修订、待验证、指定范围已修复、效果待复查或不适用；方法已启用不称教学效果已改善，相关模块回执共同引用原问题。

## 规则来源与检查能力

真实性、停止和已有授权边界共同约束所有模块；本次实际家庭条件、核实任务/取样条件限定Jane默认方法和表达偏好。起点观察的反馈时机、材料权限不能被一般纠错或字幕偏好覆盖；允许帮助转教学保留条件，而不是偷偷改评分依据。无法同时满足时按核实备用/暂停或重要变更流程处理。

| 检查方式 | 适合负责什么 | 不能据此证明 |
| --- | --- | --- |
| 程序强制 | 身份/版本、状态与动作许可、材料访问、取消/迟到、预算事件、重复处理和保存回执 | 开放回答正确或教学有效 |
| 内容核验 | 实际来源、计算/推导、题意与答案、素材关系、规则适用和核实备用 | 学生已经收到、独立完成或长期掌握 |
| 模型判断 | 本题合理变式/开放解释、困难假设与范围内指导，说明依据及未知 | 自身高置信度或第二次模型审阅成为独立证据 |

Harness采用核实条件约束提案，不把所有语义判断当可机械保证；关键语义不清先澄清/限制结论。共同合同修订需核对消费模块和[端到端案例](end-to-end-cases.md)，不只修改一处标签。


## 候选建议与正式需求

状态中的“待巩固与待验证项”是分维度判断的缺口/方向；evaluation的“下一课候选建议”是基于本课的可选行动；learning的“下一课需求”是综合全学科历史、计划和家庭条件后选定并保存的备课输入。三者引用同一证据，不互为竞争计划。

learning记录对每条相关候选建议的采纳、修改、暂缓或不采纳及理由，并给出实际需求版本。evaluation不因建议字段齐全自行发布需求，preparation只把候选用作讨论资料；无变化也返回沿用依据。

## 关键阻断的共同标准

一个问题只有影响以下至少一项，才可阻断相应后续路径：主要目标所需任务或核实内容；评价的独立条件、来源和证据真实性；停止/退出、必要访问权限或数据边界；上述对象的实际版本、保存完整性和可获取性。次要装饰、可选挑战或未证明有效的候选改进不自动成为阻断。

提出方给出问题身份、受影响对象/任务/使用范围、符合哪项标准、证据或未知、主责、可用替代、解除条件。无标准和范围的“关键”标签不足以作执行开关。未知必需项先待补而非假定通过；已知失败阻断原路径；有核实替代时对替代路径重新判定。全局停止/访问/数据缺陷阻断相应入口，单题缺陷仅限制依赖它的用途。

业务主责检查并解除自己提出的限制；协调层只组织接续，classroom按[开课判定](../classroom/session-start.md)综合。冲突先核对对象、版本、范围、来源和时间；实际条件仍不明则保持待补，不靠多数表决或家长同意覆盖技术事实。

## 待决定方案

方案由拟改变对象的维护模块编制，跨领域方案明确一个牵头者和关联者。最少包含方案身份/修订、原目标或计划/需求基线、具体变化、依据、影响/代价、可选替代、复查条件及有效范围。界面展示方案并接收家长对该版本的接受、拒绝或修改意见，应用层接续处理。

状态区分草案、待决定、接受/拒绝/撤回、待重新确认和已落实。依据、范围或重要条件变化时主责复核；实质不同的新方案不能沿用旧接受。接受不等于已保存生效，失败保持原已有效安排并限制依赖新方案的发布；不影响已有授权内的独立步骤。临时缩短和孩子停止不等待方案批准。

## P0最小对象字段与版本关系

字段名用于阶段1接口/数据库映射，不改变上述维护责任。P0只实现部分可独立校验的信封和引用，具体业务对象的持久化及全链执行留阶段1。

### 共同信封

- `schema_version`为结构合同版本（首版1）；`object_id`为稳定身份；`revision`为从1开始的业务修订；`kind`、`owner`明确对象及维护模块。固定修订不可覆盖，有效指针另存；无变化返回原引用与核对理由，不制造空修订。
- `realm`区分`simulation`、`adult_check`、`family`数据空间；`source_type`区分`simulated`、`adult`、`technical`、`child`、`external_real`；`learner_id`只为个人对象必填，共享对象为空并声明`scope`。来源修订保留`source_refs`，实际依赖保留`dependency_refs`，每个引用包含身份和确切修订，不能用“latest”。个人引用须同学习者、同数据空间；共享通用内容可按声明范围引用，个人检查不能冒充共享检查。
- `occurred_at`为实际发生时间，未知为空并列原因；`received_at`、`created_at`和`source_revision`分别表示取得、对象生成和来源集合修订。时间带时区，不能以上传日期代活动日期。
- `operation_id`连接原用例，`supersedes`连接更正前修订，`limitations`声明未知、来源限制与禁止结论。对象正文与实际素材的摘要校验只证明完整性，不证明事实或教学正确。
- 成人/技术来源可引用课程检查技术行为，不得成为真实儿童状态、计划采用或学习证据的来源。隔离虚构状态允许验证更新程序，始终为simulation，不写family区。来源标签由入口授权及原来源核对，不能让模型或请求任意指定为child。

### 核心状态与等待对象

A1的`activity_state`区分`running/offscreen/paused/closing/ended`；`end_reason`区分`normal/unconfirmed/stop/interrupted`，仅ended有结束边界。`core_revision`单调增加，`cancellation_epoch`在停止、暂停或取消旧待交付时递增，二者课中只在内存。`wait`含`wait_id`、`task_instance_id`、用途（确认目标/回答/澄清/再试/离屏报告/确认小结）及允许事件/动作。

状态转换由Harness核对任务分支、已交付范围、必要确认和预算：running可进入offscreen/paused/closing；恢复须核对原等待与能力；closing取得必要确认后normal结束，未确认按允许边界结束；任一未结束状态的明确停止直接ended/stop，可控中断ended/interrupted。停止后不能恢复为running；再次开课另行明确开始。模型不得直接写state、wait、修订或长期对象，模型提案越界不推进。

请求发出前取得核心快照引用，等待模型/合成时不持状态锁。回包发布时再次核对A/Q/wait/core_revision/cancellation_epoch；停止控制只核对当前A和控制权限，不受旧Q/wait阻挡。迟到交付报告可保存“曾实际交付的范围”并限制相关判断，不能撤销停止或让旧动作继续播放。
