# 跨模块共同约定

版本：1.0.0；更新：2026年10月12日；范围：逻辑设计，未实现。

本目录统一八个模块共同采用的对象含义、维护责任、执行顺序和验收结果。shared是横向约定，不是第九个业务模块，也不要求独立服务或新的Agent。

| 文件 | 负责说明 |
| --- | --- |
| [business-contracts.md](business-contracts.md) | 共同对象、权威维护者、尝试/帮助/交付、修订与处理结果 |
| [execution-recovery.md](execution-recovery.md) | 应用层用例协调、课后生效顺序、待反馈/失败接续、适用性和下一课条件 |
| [end-to-end-cases.md](end-to-end-cases.md) | 从需求到下节的完整案例、预期结果、禁止结论与未来验证范围 |

统一学科/能力/概念目录由learning维护，规则见[能力目录](../learning/capability-catalog.md)。各模块引用共同对象，保留本职责的细节，不另建相同对象或不同帮助等级；具体字段、API、数据库及代码位置后续确定。

## 使用顺序与责任

先核对共同对象与来源，再读取本次用例及涉及模块的详细设计，最后按对应案例检查预期与失败路径。八个模块各自判断业务内容，应用层协调调用与接续，interface取得输入/显示结果，platform提供技术能力和保存回执。

正式档案、状态、计划、需求等修订只有取得相应保存与业务处理依据才生效；课中课堂核心的必要内存状态立即按允许动作运行，不等待磁盘归档。评价依据与汇总家长报告分开，避免互相等待。

本轮只形成设计，案例未运行，当前儿童入口、真实API/声音和家庭数据权威不变。决定见[ADR-0009](../../decisions/ADR-0009.md)，项目入口见[design/README.md](../README.md)。
