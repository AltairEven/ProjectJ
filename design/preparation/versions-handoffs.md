# 备课版本管理与模块衔接

文档版本：1.6.1；更新：2026年10月12日；范围：逻辑设计，未实现。

备课编制与核对，curriculum保存课程及历史，其他模块按实际版本引用。版本组织说明来源和修改影响，不预定数据库、API、文件格式或实现方式。

共同对象及内容维护按[业务合同](../shared/business-contracts.md)，采用[执行顺序](../shared/execution-recovery.md)中已保存并复核适用的需求。新状态/方法/条件影响由来源模块提出，备课复核相关包，curriculum保存依赖/限制，启动采用有效范围；暂定草案和失败旧版不能自动成为可开课。

涉及继续条件的“关键”与阻断判定，统一采用[共同阻断标准](../shared/business-contracts.md#关键阻断的共同标准)。

## 依赖与版本

| 对象 | 保留的联系 |
| --- | --- |
| 下一课需求 | 上级目标/计划、相关状态修订、家庭条件与选择依据 |
| 课程包 | 实际需求/状态引用、Jane配置与策略、任务、素材、简报和核验记录 |
| 素材 | 原来源、实际内容版本、任务/用途/可见阶段、可变化范围与检查 |
| 本课教师简报 | 与同一课程、目标、素材、策略、帮助和预算一致，引用有效内容 |
| 核验与预览 | 对应检查对象/条件与课程版本，执行状态与家长原反馈分开 |
| 本次启动与课堂 | 当时课程、运行条件和检查范围，实际使用变式、帮助与结果 |

固定实际版本，不能仅引用会变化的“最新课程”“最新Jane”。Git提交不能替代业务版本或检查依据；生成内容哈希等技术选择后续决定，不要求每个逻辑部分成为独立文件。

内容对象与实际依赖遵循[课程生命周期](../curriculum/versions-lifecycle.md)：固定或本地发布可供引用/核验，缺口仍明示，备课与当前就绪另判；活动使用关系不改变课程身份。资料/资源/模板复用按[条件选择](../curriculum/discovery-reuse.md)，不默认继承全部检查。

## 修改影响与复用

- 新状态影响本课时，只检查相关目标、难度、前提和分支；关键目标/评价条件变化先由learning处理需求并按权限决定。
- 新Jane或策略版本影响方法时，核对简报、指导与受影响流程，不热更新正在进行的课堂。
- 改故事事件、数值、图片关系、操作或音频内容时，同步检查所有关联题目、答案、支架、预览和检查依据；不能只换文件。
- 仅外观或措辞调整也需判断是否影响语义、可见答案、声音或任务条件；无影响的已有检查可明确复用，不重复全部验证。
- 发布新版本保留原课程和原核验范围。已实施记录保留当时版本，后来的学生状态与方法改进不改写历史。
- 若事后发现原答案或判断依据错误，另加更正说明和修订，由evaluation/learning重审受影响结论；不能只改未来答案而保留有误的状态。

更正和影响追踪按[课程历史规则](../curriculum/history-corrections.md)连接资源、课程与实际使用，限制受影响未来使用，保留原内容和真实回答；归档或停用不自动删除必需依赖。

核验失败或依赖变化时，相关完成/就绪依据须重新判断；未受影响部分可继续保留。具体可重用范围见[verification.md](verification.md)，本次有效性见[readiness.md](readiness.md)。

## 保存与课堂生成边界

课程、必需素材、简报、核验与预览的保存状态要可解释，只有完整且依赖可获取才标交付完成。部分失败或版本冲突先明确未完成部分并保留来源，恢复同一修订，不重复创建相同成果或学习样本；具体存储一致性实现后续设计。

课堂按已有生成范围使用必要内存，不写快照或阶段档案；现场变式不悄悄改课程包。结束时按[共同封存规则](../shared/execution-recovery.md)保存实际采用内容/引用、条件和必要事件。无法取得的当时素材保留未知，不能事后重生成冒称原件，见[素材设计](multimodal-materials.md)。

## 模块交接

| 模块 | 向备课提供/从备课取得什么 | 责任边界 |
| --- | --- | --- |
| learning | 需求、相关全学科状态与条件；接收可行性缺口及替代/需求建议 | 维护计划与状态，备课不生成真实进度 |
| teacher | 唯一Jane的配置/方法与范围；接收方法不适配的有据建议 | 维护全局角色与策略，备课生产本课简报 |
| curriculum | 课程/素材库；接收课程包、实际素材、简报、核验与预览及版本依赖 | 保存内容与历史，不另建全局Jane规则 |
| classroom | 接收绑定包、允许调整/生成/备用和检查要求；启动时核对实际条件 | 管理本堂动作、预算与停止，备课不直接操作播放或启动教学 |
| platform | 生成、展示、声音、存储等实际能力和结果；接收限定用途的生产/核对需求 | 接口成功不等于内容正确；负责技术状态、取消与版本传递 |
| interface | 呈现预览与检查、接收家长必要条件反馈 | 不自建评分/就绪判断；家长不承担逐题内容核验 |
| evaluation | 根据实际使用版本提供内容/任务/帮助/素材适配问题与证据 | 真实事实和判断归evaluation；备课模拟不进入儿童状态 |

交接的最小内容为来源与实际修订、用途/目标、相关条件、对象/依赖、结果/未知与下一步。素材、答案和事实不复制出多个权威副本，只有相关摘要进入当次模型上下文，不强制额外Agent或逐轮重新备课。

课堂执行按[职责与统一交接](../classroom/boundaries-events.md)使用事件/动作/反馈；备课声明任务用途、允许路径/材料、能力与确认/备用条件，具体设备操作交interface/platform。课后取[实际收尾信息](../classroom/closing-handoffs.md)，不以动作生成或播放成功冒称完成，入口变化与实际帮助保留评价条件。

按[评价交接](../evaluation/handoffs.md)取得任务/素材/分支/预算不适配和[备课课堂对照](../evaluation/lesson-alignment.md)的实际依据、原因/许可/影响及主责关联。以最新有效learning需求和适用Jane版本修订，只改受影响部分并回报实际检查/完成范围；保留原课前基线，不能课后改教案伪装契合，也不把修课建议当已备好。

## 课后闭环与旧项目

evaluation依据实际课堂、素材/变式、Jane策略与帮助分别分析问题：learning调整状态和下一课需求，teacher改进方法，preparation修订内容/材料/分支，platform/classroom处理运行问题。修订引用实际记录，不因为备课检查或生成次数宣称孩子改善。

今后对接需明确唯一维护入口、标识/版本和证据可访问性；成人技术资料与儿童学习证据分开，见[旧项目关系](../../docs/legacy-import.md)。

按[基础服务交接](../platform/handoffs.md)传递生产用途、必要内容/实际版本、检查范围、期限/取消与数据条件；取得实际模型/参数、素材和保存缺口。新运行配置、声音或接入只复查受影响条件，不凭技术成功标内容正确或就绪；部分保存遵循[原修订接续](../platform/storage-lifecycle.md)。
